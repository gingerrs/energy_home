# PR Andrii-fix-all → main

Цей файл визначає процедуру приймання змін. Фактичні результати CI й
незалежного review відображаються у GitHub PR; локальні тести їх не замінюють.

## Перед публікацією

- Переглянути diff, зокрема 133 видалення node_modules і два npm-маніфести.
- Перевірити, що дані UCI, середовища та локальні кеші не потрапляють у Git.
- Перевірити результати в docs/verification.md і verification_fix_all.json.
- Підтвердити зміни контрактів: Tariff.cost тепер повертає core total,
  CLI вимагає timezone, Schedule потребує реєстру device_ids.

## Порядок приймання

1. Створити PR із Andrii-fix-all до main; додати числові результати та API impact.
2. Запросити незалежного reviewer, який не є автором цих змін. Автор не
   підміняє зовнішнє схвалення власним тестуванням.
3. Дочекатися всіх чотирьох GitHub checks:
   - ubuntu-latest / Python 3.11;
   - ubuntu-latest / Python 3.12;
   - windows-latest / Python 3.11;
   - windows-latest / Python 3.12.
4. Відповісти на зауваження, повторити перевірки після виправлень і отримати
   фактичне схвалення reviewer. Перевірити запис щодо формули peak/mean.
5. Лише після успішного CI та незалежного схвалення розглядати merge.

Workflow встановлює пакет у чисте середовище, перевіряє залежності, запускає
scripts/check_install.py з робочою папкою поза checkout, усі unittest
(включно з інтеграційними), окремі CLI-тести й спільний реальний demo report.

## Рекомендовані налаштування захисту main

Адміністратор репозиторію може вимагати PR перед merge, мінімум одне схвалення,
скидання схвалення після нових комітів і всі чотири зазначені status checks.
Також варто вимагати актуальну базу main та заборонити force push і видалення
main. Це рекомендація; налаштування GitHub цією локальною роботою не змінено.
