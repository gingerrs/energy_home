# Передача W4-B — реальний річний прогін і якість даних

Відповідальний: Андрій. Reviewer і наступна власниця ролі B: Софія.
База: `main`, `26a037f`. Гілка: `feature/andrii-w4-B-year-validation`.
Задача: [W4-B](https://app.notion.com/p/3f57884616a3815e9d01e1f905ca4f96).

## Реалізація

- Відновлено запуск `scripts/prepare_data.py`: module docstring, entrypoint,
  перевірки аргументів і зрозумілі очікувані помилки без traceback.
- `read_chunks(..., year=None)` отримав опційний відбір календарного року джерела
  до chunk lookahead. Без `year` поведінка W3 зберігається; з ним потрібні
  впорядковані роки. Фізичні номери рядків залишаються початковими.
- `uci_year(..., chunk_size=1000)` очищує тільки відібрані рядки. Rejects/gaps
  інших років і перший запис наступного року не забруднюють QualityReport.
- Naive timestamp перевіряється зворотним переведенням UTC → source timezone;
  неіснуючий локальний час відхиляється, а не підміняє справжню наступну годину.
- `write_csv(..., summary=None)` зберігає старий результат int та може додатково
  зібрати фактичні межі й десяткову суму потужності. CSV пишеться по одному запису.
- Поруч із CSV автоматично зберігається `.quality.json` з джерелом, параметрами,
  межами, counts, rejects/gaps, expected/missing intervals та спостереженими kWh.

Domain, core, analytics та CLI не змінювалися. Нова колонка часу/одиниці не вводиться:
результат — UTC interval-start і power_kw, крок для UCI 1 хв, для резерву 15 хв.

## Фактична перевірка

[Контрольний JSON](../../../data/quality/w4_2008.json) містить provenance, SHA-256,
два прогони, незалежну звірку, малий зріз і резерв. [Інструкції](../../../data/README.md)
містять повні команди завантаження, підготовки й повторної перевірки.

Перевірений UCI-файл має 132960755 байтів, SHA-256
`4259c9d7ece5dbee9ab8d53682baac68d791c864f0f64a52b4043cb3b90894b7`.
Використано календарний 2008 рік: це високосний рік, 527040 рядків, а не 365×24×60.
Межі в UTC — `[2007-12-31T23:00:00Z, 2008-12-31T23:00:00Z)` за прийнятим Paris.

| Перевірка | Результат |
|---|---|
| Прийнято | 526845 рядків |
| Rejects | 195: 135 missing values + 60 неіснуючих локальних міток |
| Gaps | 16 подій, разом 195 відсутніх однохвилинних інтервалів |
| Енергія прийнятих інтервалів | `56481077/6000` kWh ≈ 9413.512833333 |
| Chunk sizes | 17 і 1000: однакові counts/quality та побайтово однаковий CSV |
| Leap day | 29 лютого: 1440 прийнятих рядків |
| Spring DST | 30 березня: 1380 прийнятих із 1440 source rows |
| Fall DST | 26 жовтня: 1440 source rows; друга фізична година не вигадується |
| Малий зріз | 12 рядків, `9461/30000` kWh, rejects=0, gaps=0 |
| Резерв | Synthetic 2008, seed=42: 35136 рядків, 7136.7368225 kWh, rejects=0, gaps=0 |

Незалежна звірка прочитала сирий UCI-файл через окремий стандартний CSV-прохід,
без production parser/cleaner, підсумувала десяткові milli-kW як цілі числа й
звіряла кожен прийнятий рядок із підготовленим CSV. Counts, межі, енергія,
gap minutes і причини rejects збіглися. Малий fixture також звірено з оригіналом.
Резерв згенеровано двічі, зіставлено побайтово й повторно прочитано через dataio.

## Тести й відтворення

```sh
python -m pip install -e .
python -m unittest discover -s tests -p test_dataio_w4.py -v
python -m unittest discover -s tests -v
python scripts/prepare_data.py synthetic --year 2008 --seed 42
```

18 нових тестів: source/UTC year boundary, scoped quality, source line numbers,
різні chunk sizes, неповний останній чанк, зупинка перед наступним роком,
обидва DST, offset timestamps, справжній контрольний зріз, високосний резерв,
metadata, CLI entrypoint, помилкові параметри/файли/порожній рік і захист входу
від випадкового перезапису виходом або quality report.
Великі файли не потрібні для CI: тести працюють офлайн на малих fixtures і резерві.
Після чистого wheel-встановлення на Python 3.12.3 проходять усі 194 тести
(176 попередніх + 18 W4-B); `pip check` не знаходить зламаних залежностей.

## Межі та передача

UCI не надає offset/fold; `Europe/Paris` — явне припущення попереднього адаптера.
Неоднозначні naive timestamps використовують fold=0, неіснуючі відхиляються.
Немає обґрунтування відновлювати невідомі вимірювання: gaps не заповнюються.
Журнал накопичує rejects/gaps, тому його пам'ять залежить від кількості дефектів.
Якщо неможливо визначити рік некоректного timestamp, відбір завершується помилкою.
Застосовувати year до джерел із невпорядкованими роками не можна.

У картці вказано 30–50 рядків особистого обсягу. Виробнича правка вийшла більшою:
крім приймального прогону тут потрібні виправлення помилок запуску, меж року,
scoped quality та DST-дефекту. Додатковий обсяг — перевірки й метадані, без
функцій інших ролей. Це відхилення від зазначеного обсягу слід погодити на review;
відповідність обліку особистого внеску M01 не заявляється автоматично.

Софії передається працюючий річний потік, контрольні числа, явно синтетичний
офлайн-резерв та регресійні тести. Незалежне review, командне погодження
нового опційного аргументу year та усна передача залишаються кроками приймання.
