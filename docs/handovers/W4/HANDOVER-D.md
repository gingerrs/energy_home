## Результат

`analytics.build_annual_report(readings, single, two, step_minutes=15,
date_from=None, date_to=None) -> str` збирає консольний звіт з потоку B:
межі й кількість інтервалів, kWh/UAH, single/two_zone, пік, нерівномірність,
зважена середня ціна, добова й тижнева таблиці. У пам'яті немає сирого року.

Використано готові `DailySummary`, `weekly_summaries`, перевірку B,
`compare_tariffs`, `profile_metrics`, `mean_price` і точний reducer C.
Групування за локальною добою та покриття 23/25-годинних днів беруться з
`daily_summaries`. Старі API збережено. Новий Python-код не містить коментарів;
є type hints/docstring, нові рядки не перевищують 100 символів.

Обсяг основної функції аналітики: 50 непорожніх рядків, плюс 3 нові імпорти.
Два наявні імпорти доповнено потрібними іменами. Окремо після рев'ю виконано
необхідну інтеграційну правку CLI й додано сумісний прапорець allow_gaps у B.
Ці зміни показані окремими файлами PR та потребують рев'ю з E/B. Тести, інструкції й збережені результати
обліковуються окремо. Метод підрахунку наведено явно для звірки норми M01.

## Числовий контракт

- Базовий тариф — перший аргумент (типово single), його ID є у звіті;
  поруч порівняння з другим тарифом (типово two_zone).
- Точні DTO об'єднуються до округлення. Показані доби отримують різниці
  накопичених округлених totals. Тому сума днів і тижнів збігається з core;
  можливе перенесення 0.01 UAH / 0.0001 kWh між сусідніми днями.
- `from <= timestamp < to`; naive, рівні й переставлені межі — `ValueError`.
- Порожній вибір — помилка; перший некоректний запис зупиняє обробку відразу.
- Пропущені інтервали між спостереженими межами пораховані явно; повністю
  відсутні доби не вигадуються. Перенесення округлення підписане у консолі.
- Реальне нульове споживання зберігає count/період, нерівномірність і mean price
  позначені «не визначено». Прогалини залишаються прогалинами.

## Передача W4-E й обмеження

E передає потік B, single/two з `tariff_from_config`, крок джерела та
результати `_parse_datetime` в `date_from/date_to`; друкує готовий рядок,
помилки переводить у ненульовий код. Повний контракт є в інструкції Demo 1.
У цьому PR є мінімальний CLI-адаптер для сучасного реєстру, справжніх тарифів
і кроку з quality.json; normal/negative subprocess та річний запуск перевірені.
Сумісність старого demo-API збережена. Фінальні review API командою, репетиція
та усна передача залишаються відкритими.

Вхід має відомий єдиний крок; інтервал належить локальній добі свого початку.
Для коректного добового розбиття сітка має збігатися з північчю.
Аналітика показує спостережений період і покриття, не стверджує повноту року.
Якість відхилених раніше джерелом рядків слід показувати з журналу B.
Функція валідує наданий потік до першої помилки: поганий запис поза вибраними
межами також не приховується. allow_gaps не накопичує журнал прогалин усередині
аналітики; кількість відсутніх точок обчислюється з меж і count. Збереження графіків використовує готовий API W3-D.
