## Результат

- `src/energyhome/domain.py`:
  - Реалізовано клас `ScheduledRun` (заморожений dataclass) для представлення одного запуску пристрою. Реалізовано сувору валідацію: перевірка порожнього `device_id` (`_check_id`), обов'язкова наявність таймзони у `start` з автоматичним зсувом до UTC, та позитивна цілочисельна тривалість `duration` (`_check_minutes`).
  - Реалізовано клас `Schedule` як незмінний контейнер запусків. Забезпечено підтримку протоколів `Iterable` та `Sized` (`__len__`), а також детерміноване сортування елементів за часом старту `start` та `device_id`.
  - Зафіксовано базові контракти оптимізації: `SavingsResult` (метрики економії), `OptimizationRequest` (вхідні параметри для алгоритмів) та `OptimizationResult` (підсумковий розклад та економія).

- `tests/test_domain.py`:
  - Додано набір юніт-тестів для перевірки коректності створення розкладу, ітерації, валідації `ScheduledRun` (включаючи обробку naive datetime та відхилення від'ємної тривалості), а також перевірки контрактів оптимізації.

Компоненти повністю відповідають вимогам домену, забезпечують строго валідований інтерфейс для подальшої оптимізації на W6 та не ламають сумісність з існуючими моделями `LoadProfile`, `House` і `Tariff`. Усі 223 юніт- та інтеграційних тестів проєкту проходять успішно.
