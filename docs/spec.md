# Контракти EnergyHome

Python 3.11+. Потужність — kW, енергія — kWh, гроші — UAH.
Мітка часу означає початок інтервалу. Періоди напіввідкриті: `[from, to)`.

## Domain і розрахунки

`MeterReading(timestamp, power_kw)` зберігає сирий запис; dataio перевіряє його.
`LoadProfile(timestamps, power_kw, resolution_minutes)` копіює дані, переводить
aware-мітки в UTC і перевіряє рівномірну сітку та скінченну невід'ємну потужність.
Крок — додатне ціле число, bool не допускається. Порожній профіль має довжину,
енергію й пік 0; його `start_time()` і `end_time()` повертають None.
`MeterDataError` є `ValidationError` і `EnergyError`.
Старий `load_demo_profile` для порожнього CSV повертає None; обидва варіанти
порожніх даних підтримуються аналітикою.

`SingleZoneTariff(id, name, timezone_name, rate)` і зонні тарифи реалізують
`rate_at(timestamp)` та `zone_at(timestamp)`. Фабрика `tariff_from_config`
приймає розібраний реєстр; вона не читає файлів. Зони покривають добу без дірок
і перекриттів. Ставка застосовується до всього інтервалу за його початком.

`core.calculate_cost(profile, tariff) -> CostBreakdown` повертає `energy_kwh`,
`total_cost`, `average_price`, `zone_energy` і `zone_cost`. Гроші округлюються
half-up до копійок на виході. Точні суми зберігаються у DTO для reducer
`merge_cost_breakdowns`; додавати округлені вартості довільних чанків не можна.
`Tariff.cost(profile)` делегує розрахунок у core й повертає той самий
фінальний total_cost, включно з half-up округленням; окремої формули немає.
Reducer відхиляє різні конфігурації тарифів. Окремо округлені зонні суми можуть
відрізнятися від загальної на копійку.
`profile_metrics` повертає peak, mean power, peak/mean і зважену ціну.
Нульовий знаменник дає None для відповідного відношення.

## Зведення

`ReportSummary`, `DailySummary`, `WeeklySummary` — незмінні dataclass із slots.
`build_demo1_summary(profile, tariff)` бере числа з core та межі з профілю.
Порожні дані дають відсутній період, 0 інтервалів, 0 kWh, 0.00 UAH.
`format_console_report` повертає чотири рядки без кінцевого переносу, не рахує
вартість і не друкує. Гроші відображаються з двома десятковими знаками.

`daily_summaries(profile, tariff)` та
`iter_daily_summaries(readings, tariff, step_minutes=15)` використовують одну
реалізацію. Потік приймає MeterReading або пари `(timestamp, power_kw)`.
У пам'яті зберігається одна локальна доба; дата визначається у timezone тарифу.
Покриття враховує фактичну тривалість доби, зокрема 23/25 годин.
Пропуски не заповнюються нулями; дубль, неправильний порядок або значення
відхиляються. Інтервал належить даті початку; для точного розбиття доби сітка
має збігатися з локальною північчю.

День отримує різницю округлених накопичених сум. Тому сума вартостей днів і
тижнів дорівнює фінальному core total; округлення може переносити 0.01 UAH або
0.0001 kWh між сусідніми днями. Окремий вибір періоду починає накопичення заново.
`weekly_summaries` групує у календарні тижні з понеділка; повторні дати відхиляє.

`build_annual_report(readings, single, two=None, step_minutes=15,
date_from=None, date_to=None)` повертає звіт спостереженого періоду.
Перший тариф базовий; другий, якщо заданий, служить для порівняння.
Ті самі добові підсумки використано у streaming API та річному тексті.
Порожній відбір є помилкою. Реальні нульові вимірювання зберігають count і період.

## Прилади і Schedule

`Device.profile_for((start, end), step_minutes)` будує UTC-сітку; межі aware,
тривалість додатна й кратна кроку. Моделі: FixedDevice працює весь період,
CyclicDevice — один фіксований цикл, ThermostaticDevice — повторний duty-cycle.
Тільки CyclicDevice позначений shiftable. Хвилини моделі відносні до початку
періоду, а не до локальної півночі.
`detect_events` використовує hysteresis: on_threshold > off_threshold;
пороги скінченні числові без bool. Кінцеве штучне вимкнення не додається.

`ScheduledRun(device_id, start, duration)` перевіряє непорожній id, aware start
і додатну цілу тривалість у хвилинах. Start нормалізується до UTC.
`Schedule(runs=(), *, device_ids=())` — незмінний контейнер; кожен запуск має
належати явно переданому реєстру id. Непорожній розклад без реєстру відхиляється.
Для House передавайте `device_ids=(d.device_id for d in house.devices)`.
Порядок ітерації: UTC start, потім device_id.

`SavingsResult` містить baseline_cost_uah, optimized_cost_uah, savings_uah,
savings_percent. `OptimizationRequest` містить house, tariff, period,
step_minutes; `OptimizationResult` — schedule і savings. Це DTO, а не готовий
оптимізатор. Для W6 заплановано `Schedule.validate(house, windows, period,
step_minutes) -> None`: перевірка вікон, сітки, перекриття запусків одного
приладу й сумарної потужності; порушення мають давати ScheduleConflictError.
Цей майбутній метод у поточному API не оголошений і не підмінений заглушкою.

## CLI, кеш і графіки

`report --input PATH --tariff single --tariffs CONFIG` читає CSV потоком.
`--tariffs` необов'язковий: типово config/tariffs.json, потім tariffs.demo.json.
Старий формат дозволяє лише `single: {rate: number}` без підставленої ставки.
`--from` і `--to` незалежно необов'язкові, але кожна передана межа має Z або
явний offset. Рівні й перевернуті межі відхиляються. Крок читається з сусіднього
`.quality.json`, типово 15 хвилин. Успіх — stdout/0, помилка даних — stderr/1,
помилка синтаксису командного рядка — stderr/2.

`cache_profile` зв'язує аргументи із сигнатурою і враховує їх разом зі шляхом,
mtime/ctime у наносекундах і розміром файла. Типи значень у ключі розрізняються
(зокрема bool та int), datetime-параметри враховують UTC offset і fold. Зміна SourceConfig інвалідовує кеш.
Iterator і винятки не кешуються. У CLI кешується розібраний реєстр тарифів,
а не одноразовий річний потік. `log_call` пише виклики й винятки на DEBUG;
очікувана помилка один раз виводиться командою на ERROR.

Графіки імпортують matplotlib тільки при виклику; текстовий звіт не імпортує
matplotlib/NumPy. Вісь часу зберігає абсолютні instants і повторну DST-годину.
Ставка змінюється точно на початку інтервалу. `step_minutes` графіка типово 15.
Stacked bar використовує передані профілі; якщо є лише total, показується один
стовпчик загального навантаження без вигаданого розподілу між приладами.
Невідомі значення не генеруються. Довжини та сума профілів перевіряються.

## Політика DST і формула нерівномірності

Усередині обчислень час UTC; локальна дата й тарифна зона визначаються через
ZoneInfo(timezone_name). Явні Z/offset у CSV є абсолютними моментами й мають
пріоритет над локальним припущенням SourceConfig. Повторна осіння година з
різними offsets не є дублікатом. Naive-мітка джерела проходить локальний
UTC roundtrip: неіснуюча весняна година відхиляється. Неоднозначна осіння
мітка без offset трактується як fold=0; відсутня друга година не вигадується.
Для UCI Europe/Paris — задокументоване припущення джерела. CLI-межі завжди
потребують явного offset, тому неоднозначності меж не приховуються.

SourceConfig перевіряє timezone, одиниці, колонки, роздільник і крок до читання.
Метадані CLI також перевіряють тип і представимість кроку. Вихід за підтримуваний
діапазон timestamp/обчислення дає читабельну помилку CLI замість traceback.

Нерівномірність = peak_kw / mean_power_kw для рівних інтервалів; за mean=0
результат None. У первинному HANDOVER W4-C записано, що викладач погодив
цю формулу. Окремого підтвердження в репозиторії немає; команда має перевірити
цей запис під час незалежного review. Код реалізує саме наведену формулу.

